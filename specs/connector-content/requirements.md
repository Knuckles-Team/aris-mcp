| `CONN-ARIS-MCP-CONNECTOR-CONTENT-R003` | **EPC ontology maps EPC to the canonical workflow and rolls up to core.** `aris_mcp/ontology/aris.ttl` declares the EPC classes as leaves of the core terms: functions `:EpcHumanFunction`, `:EpcAutomatedFunction`, `:EpcDecisionFunction` and `:EpcProcessInterface` subclass the core `:EpcFunction`; `:EpcEvent` subclasses the core `:ProcessEventType` with `:EpcStartEvent`, `:EpcEndEvent` and `:EpcIntermediateEvent`; `:EpcAndOperator`, `:EpcOrOperator` and `:EpcXorOperator` subclass the core `:EpcRuleOperator`; attachment classes (organizational element, application system, business rule, data object, document) subclass `:EpcAttachment` (`:Concept`); `:EpcModel` subclasses `:ProcessModel`, `:ModelExport` `:MediaAsset`, `:AmlDocument` `:Document`, `:EpcConnection` `:Concept`. The file never declares or re-parents a core term (`:EpcFunction`, `:EpcRuleOperator`, `:ProcessEventType`, `:flowsTo`) and never uses `owl:imports`. Annotation properties `:dagNodeKind` (the closed canonical kind set plus `state` for a folded intermediate event and `graph` for the model), `:canonicalGateKind` (`and`, `or`, `xor`), `:arisTypeNum`, `:arisSymbolNum`, `:epcAttachmentRole` and `:executedByTool` carry the EPC to canonical mapping; the adapter reads them through `aris_mcp/vocabulary.py`, so the ontology is the one source of truth. Every tool named by `:executedByTool` is served. The KG ingest (`aris_mcp/kg_ingest.py`) types each object with its leaf class by TypeNum and SymbolNum first (type-name hints only as a fallback) and always emits the reified `:EpcConnection`. Caller chain: the SDK serves the file as `ontology://aris-mcp/aris.ttl`; `aris_mcp/canonical.py::epc_to_canonical` and `classify_epc_objects` call `aris_mcp/vocabulary.py::vocabulary`; `aris_ingest_model_graph` -> `kg_ingest.ingest_model_graph` -> `classify_epc_objects`. Depends on: `MEDULLA-CQ-CONN-R072.1`.
