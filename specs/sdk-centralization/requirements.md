Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-ARIS-MCP-SDK-CENTRALIZATION-R001` | **Capabilities come from the SDK (rollup).** The connector must use the SDK for HTTP, retry, TLS and optional dependencies. Children `.1` to `.4` deliver it. | See each child. |
| `CONN-ARIS-MCP-SDK-CENTRALIZATION-R001.1` | **Governed client.** The API client and the OAuth token request must send HTTP through the SDK governed client and must not import `requests` (`SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`). Bearer and basic credentials must travel as client auth, not as default headers. Proving test: `tests/test_sdk_transport.py::test_client_is_governed_and_sends_bearer_auth`. Caller chain: The `aris-mcp` console script runs `scion_sdk.cli:serve`, which loads `aris_mcp/__init__.py::connector` (tools=`aris_mcp.mcp.mcp_aris`) builds `ArisApi` through `aris_mcp/auth.py::get_client`; `ApiClientBase.__init__` in `aris_mcp/api/api_client_base.py` calls `build_http_client`, which wraps `scion_sdk.http.client.create_http_client`, and `auth.py::_fetch_oauth_token` uses the same builder. Shape: `build_http_client` in `aris_mcp/api/api_client_base.py` creates the client from `HttpClientOptions` with `auth=` (`BearerAuth` or `httpx.BasicAuth`) and no default auth headers; the module imports no `requests`. | The session is an SDK client with bearer auth and the package imports no `requests`. |
| `CONN-ARIS-MCP-SDK-CENTRALIZATION-R001.2` | **TLS profile only.** Every connection, including the OAuth token request, must take its trust from the `resolve_tls_profile` result for the `aris` prefix (`SCION-CENTRALIZED-CAPABILITIES-R008`). The connector must not read a verification flag. Proving test: `tests/test_auth.py::test_oauth_token_fetch_uses_resolved_tls_profile`. Caller chain: The `aris-mcp` console script runs `scion_sdk.cli:serve`, which loads `aris_mcp/__init__.py::connector` (tools=`aris_mcp.mcp.mcp_aris`) builds `ArisApi` through `aris_mcp/auth.py::get_client`; `get_client` resolves the profile with `resolve_tls_profile` and passes it to `_fetch_oauth_token` (line 16) and to `ArisApi`. Shape: `aris_mcp/auth.py::get_client` calls `scion_sdk.tls.resolve.resolve_tls_profile` once and hands the `ResolvedTLSProfile` to `aris_mcp/api/api_client_base.py::build_http_client` for both the token request and the API session; no verification flag is read. | The token client is built with the resolved profile. |
| `CONN-ARIS-MCP-SDK-CENTRALIZATION-R001.3` | **Same behaviour.** Each API method must keep its path, body and result shape. A status of 400 or more must raise `API error: <status> - <text>`. Proving test: `tests/test_sdk_transport.py::test_request_shapes_are_unchanged`. Caller chain: The `aris-mcp` console script runs `scion_sdk.cli:serve`; the tools `aris_model` and `aris_object` in `aris_mcp/mcp/mcp_aris.py` call `ArisApi.list_models`, `get_model`, `list_model_objects` and `list_model_connections`, which call `aris_mcp/api/api_client_base.py::ApiClientBase.request` (line 94). Shape: `ApiClientBase.request` sends `params`, `data` or `json` through the governed session and raises `Exception(f"API error: {status} - {text}")` for status 400 or more, using `_parse_response_body` for the result. | A request sends its JSON body and an error status raises as before. |
| `CONN-ARIS-MCP-SDK-CENTRALIZATION-R001.4` | **SDK floor.** The package must depend on `scion-sdk[mcp]` at the latest release floor and must not pin `requests` (`SCION-CENTRALIZED-CAPABILITIES-R040`). Proving test: `tests/test_sdk_transport.py::test_dependencies_come_from_the_sdk`. Caller chain: Installing the package resolves `dependencies` in pyproject.toml; the `aris-mcp` console script (`scion_sdk.cli:serve`) then imports `scion_sdk.http.client` and `scion_sdk.tls.resolve` used by `aris_mcp/api/api_client_base.py`. Shape: pyproject.toml `dependencies` lists `scion-sdk[mcp]>=0.6.4,<0.7.0` and no `requests`; the check is a text read of pyproject.toml as done in `tests/test_sdk_transport.py`. | `pyproject.toml` has no `requests` pin and the SDK floor is `0.3.11` or later. |
