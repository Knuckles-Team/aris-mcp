Every requirement this specification owns, with the proof that closes it. The generator computes each ID's delivery state; this file defines what each ID means. | ID | Requirement | Verification |
|---|---|---|
| `CONN-ARIS-MCP-R001` | **Source resolution, typed refusals and health.** `aris_mcp/source.py::resolve_mode` resolves `live` when `ARIS_API_BASE` is set, `fixture` when `ARIS_REPOSITORY_DIR=fixture`, `files` when `ARIS_REPOSITORY_DIR` names a directory of AML exports, else `unconfigured`; `aris_mcp/auth.py::get_client` has no default base URL. In `unconfigured` mode every repository tool refuses `ARIS_NOT_CONFIGURED` with a remedy naming both variables, never an empty success; writes to a `files` or `fixture` repository refuse `ARIS_READ_ONLY_SOURCE`; live writes without `ARIS_ENABLE_WRITE` refuse `ARIS_WRITE_DISABLED`. A refusal is a fastmcp `ToolError` (`ArisRefusal`) whose message is the JSON object `{code, message, remedy, details?}`. The server builds, lists its tools and answers `/health` 200 in every mode; the resolved mode is logged once when the server is built; `aris_get_source_status` reports mode, repository, model count and whether writes are enabled. Caller chain: `aris_mcp:connector` (`aris_mcp/__init__.py`) -> `extra_registrations` `source.log_resolved_mode`; every repository tool in `aris_mcp/mcp/mcp_aris.py` -> `source.get_source`. Shape: `aris_mcp/source.py` holds `SourceConfig`, `resolve_mode`, `get_source`, `FileRepository`, `source_status`, `log_resolved_mode` and `ArisRefusal` (a fastmcp `ToolError`); reuse `scion_sdk.config.setting` and the SDK `/health` route. | `tests/test_source.py::test_unconfigured_refuses_typed` |
| `CONN-ARIS-MCP-R002` | **AML reader.** `aris_mcp/aml.py::read_aml` reads an ARIS AML export (`Group`, `ObjDef` with `TypeNum`/`SymbolNum`/`GUID`, nested `CxnDef`, `Model`, `ObjOcc`, `CxnOcc`, `AttrDef` `AT_NAME` as `AttrValue` text or `StyledElement`/`PlainText`) into the record shapes of the live client: model `{guid, id, name, type, groupPath, attributes}`, object `{guid, id, name, type, symbol, attributes}`, connection `{guid, id, type, sourceObjectId, targetObjectId}`. It refuses a document type declaration, entity declarations and documents above 16 MiB (`AML_INVALID` at the tools). Caller chain: `aris_import_aml`, `aris_export_canonical_workflow` and `source.FileRepository` -> `read_aml`. Shape: `aris_mcp/aml.py` holds `read_aml`, `AmlModel` and `AmlError`; reuse `defusedxml.ElementTree.fromstring(forbid_dtd=True)`. | `tests/test_aml.py::test_reader_refuses_doctype_and_entities` |
| `CONN-ARIS-MCP-R003` | **AML writer.** `aris_mcp/aml.py::write_aml` writes model, object and connection records as AML (group path, object and connection definitions with GUIDs, model occurrences) that `read_aml` reads back to the same records; writing that result again gives the same text. Caller chain: `aris_export_aml` and `aris_import_canonical_workflow` -> `write_aml`. Shape: `aris_mcp/aml.py::write_aml` builds the tree with the standard library `xml.etree.ElementTree`; reuse `AmlModel`. | `tests/test_aml.py::test_writer_round_trips_through_the_reader` |
| `CONN-ARIS-MCP-R004` | **EPC to canonical workflow.** `aris_mcp/canonical.py::epc_to_canonical` turns EPC records into a `medulla.process.canonical/v1` document: control objects (function, event, rule operator, process interface) and control flow only; functions classified by their attachments (performer via `CT_EXEC_*` and no application system -> `human` with the performer as role; a business rule or decision object -> `decision` with the rule name as ref; else `agent`; `ST_PRCS_IF` -> `call`); events with no incoming flow -> `start`, no outgoing -> `end`; an event after an XOR/OR split folds into the flow condition (annex `epc-condition-event`), any other intermediate event folds away (annex `epc-state-event`); operators become `branch`/`fork`/`join` by degree with gate `and`/`or`/`xor`, a join-and-split operator becomes two steps; unknown attachments go to the annex as `epc-attachment`. Labels are NFC, whitespace-collapsed and trimmed. Steps are numbered `s1..sn` by Kahn's algorithm with the contract key; flows are sorted; the digest is SHA-256 over `{schema, steps, flows}` with sorted keys and compact separators. The mapping comes from the ontology annotations. Caller chain: `aris_export_canonical_workflow` (`aris_mcp/mcp/mcp_aris.py`) -> `epc_to_canonical`. Shape: `aris_mcp/canonical.py` holds `epc_to_canonical`, `number_steps`, `build_canonical`, `compute_digest` and `normalize_text`; reuse `aris_mcp/vocabulary.py::vocabulary`. | `tests/test_canonical.py::test_epc_to_canonical_equals_the_golden` |
| `CONN-ARIS-MCP-R005` | **Canonical workflow to EPC with loss rules.** `aris_mcp/canonical.py::canonical_to_epc` validates a canonical document (`PROCESS_CANONICAL_INVALID`), restores EPC alternation (a synthesized `<label> completed` event between two functions, a condition event per conditioned split arm, start and end events), restores annexed events and unknown attachments with their ids on a same-source (`aris`) export, and lists what EPC cannot express as `losses` (`typed-trigger`, `boundary-event`, `default-flow`, `event-based-gateway`, `decision-table` for a canonical from another format, `unassigned-human-step`, and the other format's annex constructs). With `strict=true` a lossy export refuses `PROCESS_EXPORT_LOSSY` listing the losses. A same-source round trip keeps the digest and the annex. Caller chain: `aris_import_canonical_workflow` -> `canonical_to_epc` -> `aml.write_aml`. Shape: `aris_mcp/canonical.py` holds `canonical_to_epc`, `validate_canonical` and `CanonicalError`; reuse `aml.write_aml` and the ontology vocabulary. | `tests/test_canonical.py::test_same_source_round_trip_keeps_digest_and_annex` |
| `CONN-ARIS-MCP-R006` | **Fixture repository.** `aris_mcp/fixtures/repository/` bundles the invoice-approval sample and a supplier-onboarding model with an OR split and join, a process interface and an unknown attachment. With `ARIS_REPOSITORY_DIR=fixture` the read tools serve it and tag every response `"repository": "fixture"`; with a directory path they serve that directory's AML exports read-only and skip unreadable files. Caller chain: `source.get_source` -> `source.FileRepository`. Shape: AML files under `aris_mcp/fixtures/repository/` packaged by `pyproject.toml` package-data; reuse `source.FileRepository`. | `tests/test_source.py::test_fixture_repository_serves_the_samples_through_read_tools` |
| `CONN-ARIS-MCP-R007` | **One typed tool per operation.** The server lists exactly `aris_get_source_status`, `aris_list_models`, `aris_get_model`, `aris_list_model_objects`, `aris_list_model_connections`, `aris_get_model_attributes`, `aris_set_model_attributes`, `aris_set_object_attributes`, `aris_ingest_model_inventory`, `aris_ingest_model_graph`, `aris_ingest_model_export`, `aris_import_aml`, `aris_export_aml`, `aris_export_canonical_workflow` and `aris_import_canonical_workflow`, each with typed parameters and tool annotations; no tool takes `action` or `params_json`, and `aris_model`, `aris_object` and `aris_ingest_models` are gone. `connector_sources.py` and `ontology/mappings/source.yaml` name `aris_list_models`. Caller chain: the `aris-mcp` console script (`scion_sdk.cli:serve`) -> `aris_mcp:connector` (`tools="aris_mcp.mcp_server"`) -> `register_aris_tools`. Shape: `aris_mcp/mcp/mcp_aris.py::register_aris_tools` with `Annotated` pydantic parameters and `ToolAnnotations`; reuse the SDK tool discovery of `register_<tag>_tools`. | `tests/test_tool_surface.py::test_surface_is_one_typed_tool_per_operation` |
| `CONN-ARIS-MCP-R008` | **Cross-source equivalence fixture.** `tests/fixtures/invoice-approval.aml` (strict EPC) and `tests/fixtures/invoice-approval.bpmn` (BPMN 2.0) describe one 12-step process.
